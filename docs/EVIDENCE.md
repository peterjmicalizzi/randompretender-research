# Evidence and attribution

Every claim identifies the mathematical statement, relevant object and relations, assumptions, and exact evidence revision. A permutation of coordinate labels is not an intrinsic identity for an individual vertex. Use explicit maps when comparing representations; invariants alone cannot establish equivalence.

The same point set with different edge relations is a different input for a graph calculation. Quaternion multiplication edges in the starter experiment are **Cayley edges**, not the geometrical edges of the 600-cell.

## Current evidence presentation

Records list attached evidence and open requests. There is no automatic validity engine yet. GitHub labels, reactions, issue closure, PR approval, and merges do not assign validity. The initial script/result pair is a single implementation with internal exact-arithmetic checks, not an independent reproduction or Lean proof.

The intended future display derives separate assessments from accepted records: computed for these inputs; independently reproduced within scope; challenged by an unresolved applicable objection; refuted as stated by a checked counterexample; formally established under stated assumptions; superseded by a reviewed revision. These can coexist. Rules and their versions must be inspectable. Human judgment about applicability and implementation independence must itself be attributed, not hidden in a status toggle.

Corrections should preserve the original and link to a revised claim. Dependencies may indicate affected work without declaring every dependent claim false. Until propagation is implemented, maintainers add links and notify participants in the relevant issues.

## Review example

> Reviewed the operator derivation in revision 8. Did not rerun the experiment.

The reviewer receives credit for that scope, with a stable GitHub comment or PR URL and the actual full commit SHA of revision 8. A credential is context; it is not blanket approval. Reproduction records state the implementation and environment, actual comparison, and shared dependencies. Re-running the same script is replay, not separate-implementation reproduction.

## Citations

Reference the repository URL, full commit SHA, record ID, and relevant evidence/review URLs. Use GitHub's permalink (press Y while viewing a file) to pin a revision. The repository's CITATION.cff identifies the library as a whole, not authorship of every contribution. No DOI is claimed. Maintainers can later archive selected releases with an archival service.
