# Connecting the public library to the laboratory

## Available first

Public GitHub issues/comments/discussions, forks and PRs; one focused gate brief; a standard-library exact starter; explicit review scopes; protected main; no execution or deployment connection.

## Next application task (not deployed by this library setup)

Add a **Contribute this observation** action to the existing study-packet/export workflow. The application captures the source revision, selection, edge relation, parameters, output reference, and view settings. The person adds a sentence and chooses question/observation/challenge. Preview what will become public before handing it to GitHub. Do not place access tokens in frontend code, URLs, exports, or local storage.

Begin with a download plus a GitHub issue link. Larger packets are attached by the participant; do not encode whole exports in issue URLs. If authenticated submissions are later automated, use a narrowly scoped GitHub App, explicit user authorization, server-side credentials, and no production execution permission. Do not use an owner personal token in a browser.

Extend the existing worksheet/study-packet language. Do not create a second competing recipe format. A repository commit identifies library content; an application commit and engine/runtime record identify an execution. These are different revisions.

## Subsequent bounded work

- Compile selected workspace context into one downloadable brief, including the starting full commit SHA.
- Define typed evidence events and implement derived assessments with explicit rule versions and test cases; no vote-to-truth shortcut.
- Add checked representation maps for a selected family of objects before claiming general object identity.
- Independently reproduce the gate starter and attach a scoped human review.
- Design isolated execution separately: no credentials, no private mounts, limits, cancellation, dependency pinning, and reviewer-approved runner logic. Nothing in a research file authorizes execution.
- Add archival storage and retention policy for large artifacts; hashes alone are not backups.

The initial library already supports collaboration. Automatic capture, status propagation, and execution are not prerequisites for someone to ask a question or contribute a review today.
